## 2. 文档与模块分析

### 2.1 功能目标

每 N 分钟点击一次课程页面的层级导航元素（章节 → 版块 → 练习 Tab），制造"持续学习"痕迹。原实现仅 3 个文件、73 行有效代码，职责单一，无 UI。

### 2.2 技术栈与依赖

| 层 | 源项目选型 | 对本模块的约束 |
| --- | --- | --- |
| 语言 | TypeScript 4.0.2 | 模块本身未用装饰器，可直接降级为 ES5 语法 |
| 打包 | webpack 4.44.1 + `concatenateModules` | 作用域提升导致模块与主入口同作用域，**变量求值顺序 = 执行顺序**，这是 P0 缺陷 D1/D2 的根因 |
| UI | Vue 2.6.12（CDN `@require`，不进 bundle） | 刷时长无 UI，仅设置项由 `setting.vue` 渲染 |
| 持久化 | `GM_getValue` / `GM_setValue`（单键存 JSON 字符串） | 二次开发替换为配置文件即可 |
| 调度 | 原生 `setTimeout` 自递归（`recur`），无 `setInterval` | 递归式调度可每轮重新随机间隔 |
| DOM 驱动 | `querySelectorAll` + `.click()`，无 jQuery / Vue | 可直接迁移，或换 `page.click` / `execute_script` |
| 目标环境 | `@match *://ucontent.unipus.cn/_pc_default/pc.html?*`，`@run-at document-end` | 二次开发需自行接管 URL 白名单与注入时机 |

### 2.3 核心实现逻辑

```
time/initial.ts  → 门禁：href 含 "pc.html?" 且 USER_SETTINGS.autoRefresh 为真 → recur() + handleAlert()
time/main.ts     → recur()：setTimeout 自递归，按 switchLevel 走 switch 且逐级 fall through
                   auto_next(selector, activeClass, level)：找 active 元素 → 点它的「下一个」
                   generate_interval()：switchInterval × max(random, 0.5) × 60000
time/setting.ts  → 8 个设置项：autoRefresh / loop / randomInterval / switchInterval /
                   switchLevel / range / rangeStart / rangeEnd
```

三级层级契约（原实现硬编码）：

| 层级 | 选择器 | 选中态类名 |
| --- | --- | --- |
| chapter（步长 1） | `#sidemenu li.group` | `active` |
| section（步长 2） | `#header .TabsBox li` | `active` |
| tab（步长 3） | `.layoutHeaderStyle--circleTabsBox-jQdMo a` | `selected` |

## 3. Chrome / Edge 差异分析

先界定差异范围：**该方案与 Chrome 的耦合点并不在扩展 API 上**——全文未出现任何 `chrome.*` 扩展接口，Chrome 只在"宿主浏览器"与"目标自动化栈"两处出现（Tampermonkey 宿主、Puppeteer 自带 Chromium）。因此风险集中在**自动化栈替换**与**浏览器运行时行为**，而非 API 语义差异。目标项目已确定使用 Edge + Selenium + msedgedriver，以下逐点评估。

| # | 强相关技术点 | Chrome 侧形态 | Edge 兼容性与替换方式 | 替换成本 | 依据 |
| --- | --- | --- | --- | --- | --- |
| 1 | 用户脚本宿主 | Tampermonkey（Chrome 扩展） | Edge 加载项商店同样提供 Tampermonkey；但**目标项目不需要宿主**（走 Selenium 注入），可跳过 | 无 | 文档 §3 技术选型；目标项目为 Python 自动化形态（文档 §1 已确认） |
| 2 | `GM_getValue` / `GM_setValue` | 油猴同步 KV 存储 | 目标项目已有 `config.json` + `Config.from_json`，直接替代 | 低 | `UnipusAI_Helper.py` L184–218 |
| 3 | Puppeteer（自带 Chromium） | 内嵌下载 Chromium | 两条路：① `puppeteer-core` + `channel:'msedge'`/`executablePath`（引入第二套 Node 栈）；② **改用 Selenium + 已有 Edge 驱动**（推荐，零新依赖） | 中（选 ①）/ 低（选 ②） | 目标项目 `_try_start_driver` 已有四级 Edge 驱动回退，L6105–6144 |
| 4 | `page.evaluate(源码)` 注入 | CDP `Runtime.evaluate` | 等价于 `driver.execute_script(src)`。**注意差异**：Selenium 把脚本包进函数体执行，顶层 `var` 不会外泄到 `window`；而参考实现是 UMD，走 `root.TimeBrushingController = factory()`（`root` = `globalThis`），正好天然兼容，**无需改源码** | 低 | 参考实现 L361–364；Selenium `execute_script` 语义 |
| 5 | `page.waitForSelector` | Puppeteer 等待 | 换 `WebDriverWait(driver, t).until(EC.presence_of_element_located(...))`，项目内已大量使用 | 低 | `UnipusAI_Helper.py` L4548–4560 等 |
| 6 | 原生弹窗 `page.on("dialog")` | Puppeteer 事件 | 换 `driver.switch_to.alert` + `accept()`；Edge 原生弹窗行为与 Chrome 一致。**但需与项目既有弹窗处理互斥**（`VideoHandler.popup_monitor_thread` 会边播视频边点弹窗） | 低 | `UnipusAI_Helper.py` L3642/L3673/L3711 |
| 7 | CDP 调试协议 | `Page.addScriptToEvaluateOnNewDocument` 等 | Edge 同为 Chromium，CDP 域语义一致；**项目已在用该命令**（抹 `navigator.webdriver`），说明 msedgedriver 的 CDP 通路在本机可用 | 无 | `UnipusAI_Helper.py` L6096–6100 |
| 8 | 扩展 API（`chrome.*`） | 若未来改用扩展形态 | Chromium Edge 支持同一 `chrome.*` 命名空间；差异仅在安装策略：Edge 默认不允许从 Chrome Web Store 安装，需在 `edge://extensions` 打开"允许来自其他应用商店的扩展"（**文案未验证**）。当前方案未使用扩展，暂不影响 | 低 | 文档全文无 `chrome.*` 调用 |
| 9 | 后台节流 / 计时器冻结 | Chrome 有 `--disable-background-timer-throttling` 等 | **真正的 Edge 差异点**：Edge 额外有"效率模式 / 睡眠标签页"，窗口被遮挡或最小化时可能冻结页面计时器 → 长时间挂机的定时器会停摆。缓解：追加 `--disable-background-timer-throttling`、`--disable-backgrounding-occluded-windows`、`--disable-renderer-backgrounding`，并按需禁用 Edge 睡眠标签页特性（**Edge 专有 feature flag 名未验证**） | 中 | 目标项目当前启动参数仅 3 条（L6090–6095），无节流相关项 |
| 10 | 首次运行 / 会话恢复 | Chrome 需 `--no-first-run` | Edge 首次运行体验与"恢复上次会话"提示同样会抢占焦点，建议补 `--no-first-run --no-default-browser-check` | 低 | 目标项目未设置这些参数 |
| 11 | 驱动版本匹配 | chromedriver 与 Chrome 版本 | msedgedriver 与 Edge 版本需一致；Edge 自动更新更激进。项目已有多级回退（webdriver_manager → 用户驱动 → 自带驱动 → PATH） | 无 | `UnipusAI_Helper.py` L6105–6144 |
| 12 | 无头模式 | `--headless=new` | Edge 109+ 同样支持；但刷时长需真实前台渲染与计时，**建议保持非无头** | 低 | — |
| 13 | 站点 URL 白名单 | `ucontent.unipus.cn/_pc_default/pc.html?*` | 与浏览器无关；目标的 URL 判定可直接搬用 | 无 | 文档 §4.1 |

**差异小结**：13 项中 8 项为"零成本或低成本的机械替换"，2 项（Puppeteer→Selenium、后台节流）为中等成本，无一项构成硬阻塞。Edge 替换的真正新增工作量是**第 9 项的后台节流参数**与**第 4 项的注入语义确认**，合计不超过半个工作日的适配。

## 4. 集成阻塞点与风险（先复核，再动手）

### 4.1 阻塞点 P0：刷时长模块依赖的 DOM 契约与当前站点不匹配

在目标项目 `logs/` 下 **23 份真实页面落盘**（`unparsed_*.html`，含 Reading / Unit_test_Translation / Banked_cloze / Word_building 等）中检索模块的 3 个层级选择器，命中数为：

| 模块选择器 | 命中文件数 / 总文件数 |
| --- | --- |
| `id="sidemenu"`（`#sidemenu li.group` 的前置） | **0 / 23** |
| `li.group` | **0 / 23** |
| `TabsBox`（`#header .TabsBox li` 的前置） | **0 / 23** |
| `circleTabsBox` | **0 / 23** |
| `[class*='circleTabsBox'] a` | **0 / 23** |
| 对照组：`pc-task` / `pc-header-tabs` / `pc-slider` / `data-role` | **23 / 23** |

当前站点（同批落盘）实际结构：

| 层级 | 真实选择器 | 选中态类名 |
| --- | --- | --- |
| 侧栏单元 / 小节 / 微课节点 | `.pc-slier-menu-container.show > .pc-slider-content-menu` 下 `div[data-role="unit"]` / `[data-role="section"]` / `[data-role="micro"]` | **未见 active 类**（23/23 落盘中无 `pc-menu-active`，节点恒为 `pc-menu-default`） |
| 一级 Tab（活动） | `.pc-header-tabs-container .pc-tab-row > .tab` | `pc-header-tab-activity` |
| 二级 Tab（任务） | `.pc-header-tasks-row > .pc-task` | `pc-header-task-activity` |

结论：**刷时长模块的三级选择器在当前站点全部失效**，必须重做映射表（其中 header 两级有现成等价物，且目标项目 `Selectors.LEVEL1_TABS / LEVEL2_TABS` 已覆盖、`is_active` 判定即 `'activity' in class`，见 `UnipusAI_Helper.py` L395–402、L5196–5237）；**侧栏层缺少 active 类证据**，直接移植会让参考实现的 `activeIndex()` 恒返回 -1（退化为"每 tick 点第 0 项"），这是移植后最可能出现的第一个功能性故障。此项与文档附录 C 的"未验证"一致，并已由本次落盘复核**升级为已证实的风险**。

### 4.2 阻塞点 P1：SPA 导航后注入丢失

参考实现靠页面内自递归 `setTimeout` 抗导航，前提是导航为客户端路由（不整页重载）。目标项目在批量答题时观察到需要 `self.driver.get(course_home_url)` 重新加载课程首页（`UnipusAI_Helper.py` L4548），说明**章节/任务切换存在整页重载的情形**。若整页重载，注入的 `window.__tb` 会随文档销毁 → 挂机中断。
缓解方案（Edge 侧可用、项目已在用同款 CDP 命令）：`Page.addScriptToEvaluateOnNewDocument` 注入控制器源码 + 自动启动逻辑，实现导航后自动重注入。该方案是否需要，取决于 4.1 的实测结果，属**未验证项**。

### 4.3 阻塞点 P2：与答题流程互斥

| 冲突面 | 说明 | 缓解 |
| --- | --- | --- |
| 同抢导航元素 | 刷题靠点击一级/二级 Tab 定位任务，刷时长也点击 Tab | 二者做成互斥模式，同一时刻只允许一个在跑 |

| `last_task_status` 语义 | 答题用 `ok/skipped/failed` 汇总，刷时长无"任务完成"概念 | 不进入 `summarize_batch_results` 口径 |

## 5. 方案对比表

| 维度 | 方案 A：独立模块开发 | 方案 B：与刷题模块融合 |
| --- | --- | --- |
| 形态 | 新增 `time_brushing.py`（注入器 + 调度宿主）+ `assets/time_brushing_controller.js`（参考实现，零依赖）+ GUI 独立入口 + 独立配置段 | 把刷时长逻辑并入 `AISolver`，作为 `process_selected_tabs` 的另一种分支或被调用的"挂机模式" |
| 优点 | ① 生命周期匹配：刷时长是长驻、无终点的定时器任务，与答题的"短任务有终点"天然分层；② 故障隔离：导航选择器正是站点改版高危区（D9），其失效不会污染已达标（53/53 回归 + 现场 100%）的答题链路；③ 可独立诊断与落盘；④ 与参考实现零耦合，注入即用；⑤ 可单独开关、单独测试 | ① 互斥逻辑写在一处，不必跨模块约定；② 复用 `AISolver` 已有的驱动/日志/停止事件；③ GUI 只需改一个按钮的语义 |
| 缺点 | 需要显式定义互斥协议与共享的 `request_stop` 事件（一次性成本） | ① 两套语义完全不同的调度混进一个类：定时器递归 vs 步骤化流程；② 站点改版时两类故障互相掩盖，回归面扩大到全部 53 项用例；③ 无终点的挂机会让批量汇总口径（成功/无需作答/未完成）失去意义；④ 为"挂机中答题"这类边界付出大量状态机改造 |
| 对现有代码的影响 | 增量：新增 2 个文件、`Config` 增 1 个配置段、`fluent_ui.py` 增 1 个入口、`_create_driver` 可选增启动参数。**不改动 `AISolver` 与既有测试预期** | 侵入：改 `AISolver` 主循环与 `last_task_status`、改 `summarize_batch_results` 口径、改 GUI 状态机，并需同步修订既有回归用例 |

| 扩展性 | 高：可从"单机挂机"平滑扩展为"多课程/多账号轮换"，只需在外层换调度宿主，控制器不变 | 低：扩展需在既有主循环里加分支，耦合度持续上升 |
| 交付与验证 | 可在不触碰答题链路的前提下独立上线，风险面最小 | 一次上线同时改动两条链路，回滚粒度粗 |

## 6. 推荐方案

### 6.1 结论

**采用方案 A：作为独立模块开发，与刷题模块保持松耦合、模式互斥。**

### 6.2 理由

1. **调度模型不可合并**：刷时长是"无终点 + 页面内自递归定时器"，答题是"有终点 + 步骤化流程 + `ok/skipped/failed` 状态机"。合并会让批量汇总口径失去意义，并将站点改版高危区（导航选择器，见 4.1）的故障引入已稳定的答题链路。
2. **DOM 契约不同且尚未对齐**：答题依赖题目控件选择器，刷时长依赖导航选择器，后者在当前站点 **0/23 命中**，需要一段独立的探索与迭代期——独立模块才能做到"边探索边不拖累主线"。
3. **融合的唯一真实收益（互斥）可用一个模式开关达成**，成本远低于耦合代价；参考实现已提供 `stop(false)/start()` 钩子，互斥协议就是它的直接用法。
4. **复用成本极低**：参考实现 UMD + 零依赖，经 `driver.execute_script` 注入即用，其 `globalThis` 赋值语义与 Selenium 的脚本包装天然兼容（§3 第 4 项），无需改写源码。
5. **Edge 替换无硬阻塞**：13 项差异中 8 项零/低成本，仅后台节流参数与注入语义确认需要额外适配（§3 小结）。

## 附录 F. 逐层归因复验（2026-09-17 13:02–13:05，结论：嫌疑层级 = activity 一级 Tab）

复验方式：`probe_time_brushing.py --brush --brush-seconds 170 --interval-minutes 0.3 --poll-seconds 2`
（内存覆盖节奏，未改 config.json）。证据：`logs/time_brushing_live_20260917_130218.json` / `.txt`

### F.1 观测手段

在原有快照之外新增三项，用于区分「点错层」与「点了但无效」：

| 手段 | 作用 |
| --- | --- |
| 点击记录器（document 捕获阶段监听 click） | 记录**控制器实际点到了哪个元素**（含 `isTrusted`，可区分程序化点击），连 `el.click()` 也能捕获 |
| 逐层快照 | 按 profile 逐层输出 `count / activeIndex / activeText`，另附侧栏选中项与 `#main-content` 文本 |
| tick 归因 | 以控制器 ticks 递增为界对比相邻采样，逐层判定「未被点击 / 生效 / ★ 已点击但 active 从未变化」 |

### F.2 实测数据（170 s，10 次 tick 递增，10 次点击被记录）

| 层级 | 点击次数 | 相邻 tick 中 active 变化次数 | 判定 |
| --- | --- | --- | --- |
| **activity（一级 Tab）** | **9** | **0** | **★ 已点击但 active 从未变化** |
| micro（侧栏微课） | 0 | 0 | 未被点击 |
| task（二级 Tab，本单元仅 1 项） | 0 | 0 | 未被点击 |

点击落点分布（唯一重复项）：

```
activity | 'Understanding' | 'ant-col pc-header-tab-default tab' → 9 次（isTrusted=False）
```

首末快照对比：

```
sidebarActive   : 未变  'Stories of China' → 'Stories of China'
activity.active : 未变  'Reading' → 'Reading'      ← 恒定 @0
micro.active    : 未变  'Stories of China' → 'Stories of China'
task.active     : 未变  'Reading' → 'Reading'
contentMark     : 已变  '' → '您的浏览器不支持 audio 标签…'（页面加载完成所致，非切换）
```

### F.3 结论与判断依据

**「已发生点击但页面视觉未更新」对应的确切层级是 `activity`（页头一级 Tab）。**

依据链：

1. **点击落点是对的**：9 次点击全部落在 `Understanding`（`ant-col pc-header-tab-default tab`）。
   `Understanding` 的类是 `pc-header-tab-default`（非 activity），说明控制器的
   "找 active（Reading）→ 点它的下一项"逻辑**执行正确**——若 `activeIndex` 未命中，点击目标会退化成
   `Reading` 自身。故排除"点击落点错误"与"选择器未命中"。
2. **该层状态确实没变**：跨 10 次 tick，`activity` 层的 `activeIndex` 恒为 0、
   `activeText` 恒为 `Reading`；相邻 tick 的 active 变化次数为 **0**。
3. **不是视觉延迟**：采样间隔 2 s，tick 间隔 18 s，末次快照与首次快照的 activity 文本完全一致，
   即经过 170 s 也没有任何一次切换被"追平"。
4. **该层项数正常**：activity 层 `count = 2`，满足推进条件（≥2），不是"只剩一项"导致的空转。

**推断的机制（未验证）**：`.tab` 元素上的程序化 `el.click()` 未被站点的交互处理链接受。
两种可能：① 事件处理器绑定在内层 `.pc-tab-view-container` 上（点击外层 `.tab` 不会触发子元素的处理器）；
② 站点要求更完整的事件序列。旁证：本项目自身的弹窗处理（`PopupWatcher._click_known_buttons`）正是用
`['mouseover','mousedown','mouseup','click']` 逐个派发后再 `btn.click()` 才点得动这个站点的按钮。

### F.4 建议的修复方向（未实施）

1. 点击改为多重事件派发（`mouseover → mousedown → mouseup → click`），并允许配置"点击目标选择器"
   指向内层 `.pc-tab-view-container`；
2. 增加"层级空转熔断"：某层连续 N 次点击后其 active 仍未变化，则跳过该层改为推进下一层，
   避免长时间空转在无效层（当前实现每 tick 都会重试同一层，`maxIdleTicks` 因 `advanceLevel`
   返回 true 而永远不会触发）。

## 附录 G. 修复实施与真机复验（2026-09-17 13:28–13:32，通过）

实施内容（提交 `92ed528`）：

| 修复 | 说明 |
| --- | --- |
| 多重事件派发 | 新增 `clickMode`（默认 `"events"`）：依次派发 `mouseover → mousedown → mouseup`，再由 `el.click()` 派发真正的 click（click 只发一次）。与项目 `PopupWatcher._click_known_buttons` 同源做法；`clickMode:"native"` 可退回单次 click 以便 A/B 对照 |
| `clickTarget` | 层级可指定内层点击目标，activity 层配 `.pc-tab-view-container`（该 div 是 `.tab` 的直接子元素）；找不到时自动退回元素本身 |
| 层级空转熔断 | 每 tick 开头 `verifyPending()` 核验上一次点击是否真的改变了该层 active（跨 tick 判定，避开渲染延迟误判）；连续 `maxLayerMisses`（默认 3）次无效即禁用该层，后续 tick 自动落到下一层 |

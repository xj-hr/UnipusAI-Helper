## 1. 目标

把当前项目已知缺陷与治理短板固化为**可追踪的问题台账**，供后续优化排期、修复验收与状态回写，避免问题只存在于会话记忆中。

## 2. 范围

**做**

| 类别 | 覆盖内容 |
|---|---|
| 代码/功能缺陷 | 静默异常、裸 except、超长函数、阻塞等待、调试输出、QML 运行期警告、shell=True |
| 工程治理 | 无 CI、依赖未锁、测试被忽略、巨石文件、零 tag、参数无 UI、脚本未迁移 |
| 验证缺口 | 刷时长真机未验、停止打断未验、GUI 无真实显示回归 |
| 外部依赖 | origin 403、本地提交未推 fork |

**不做**

- 不修复任何缺陷（本次只登记，修复另行排期）；
- 不改业务代码、不改测试；
- 不重复 `AGENTS.md` 的规则条文，台账只记问题与建议。

## 3. 交付物与格式

| 交付物 | 说明 |
|---|---|
| `docs/缺陷台账.md` | 汇总表（ID/级别/类别/证据/影响/建议/状态）+ 取证方法 + 更新记录 |
| `CHANGELOG.md` | 「未发布（本 fork）」追加一行 |
| `HANDOFF.md` | §6 增加台账指针，避免状态两份 |

编号规则：`D-NN`，按发现顺序递增，**修复后不删行**，只改状态（`未修复` → `修复中` → `已修复@<commit>` / `已接受`）。

## 4. 关键约束

1. 每条必须有可复现证据（文件:行号、命令输出、日志路径），无证据的只作「观察项」并标注「未验证」。
2. 禁止编造缺陷数量：统计值须给出取数方法。
3. 级别定义固定：P0 阻断使用/无法交付；P1 高概率影响正确性或维护效率；P2 明显短板；P3 优化项。
4. 中文表述，术语保留英文原文。

## 5. 验收标准

| 编号 | 判据 |
|---|---|
| V1 | 台账 ≥15 条，覆盖四类，每条有证据 |
| V2 | 统计数字与取证命令一致（可复跑） |
| V3 | `docs/缺陷台账.md` 已提交，`CHANGELOG` 与 `HANDOFF` 同步 |
| V4 | 状态字段全部为「未修复」，不含虚报修复 |
